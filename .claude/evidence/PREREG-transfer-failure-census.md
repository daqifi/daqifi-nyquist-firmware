## THE AXIS THAT DECIDES THE ANSWER (conv-fw's structural finding, which I am testing, not assuming)

*The protections that travelled are behind a **shared callee**; the ones that did not are where a
second file **reinvented** instead of calling.* So each row gets classified:

- **SHARED-CALLEE-PREVENTABLE** — both sites could have called one function/script; the duplication
  is the defect, and a single implementation would have carried the fix automatically.
- **NEEDS SOMETHING ELSE** — the two sites cannot share a callee (different languages, different
  contracts, prose vs code, different repos), so only an explicit cross-file check could have caught
  it.
- **NOT A TRANSFER FAILURE** — the search above succeeded; the second site did not need it.
