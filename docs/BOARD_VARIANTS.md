### Board Variants

- **NQ1**: Basic variant configuration
- **NQ2**: Enhanced variant with additional features
- **NQ3**: Full-featured variant

Each variant has specific:
- Channel counts and types
- ADC/DAC configurations
- Power management settings
- UI configurations

### Switching Between Board Variants

The firmware supports building for different board variants using MPLAB X configurations.

> **`default` IS the NQ1 configuration.** There is no separate `Nq1` conf — it was
> deleted because it had silently diverged: it built at **-O1** and lacked the
> per-file overrides for `FreeRTOS_tasks.c` and `tfm.c`, while `default` builds at
> **-O3** (see "Compiler Optimization Level" in `docs/BUILD_AND_TOOLCHAIN.md`). Every NQ1 image ever flashed, every
> characterization number in this file, and every release cut came from `default`;
> `Nq1` was never validated on hardware. All release tooling — `cut_release.sh`,
> `check_build_config.py`, the CI guard — scopes to `<conf name="default">`.

1. **In MPLAB X IDE**:
   - NQ1: use the `default` configuration (selected on open)
   - NQ3: Right-click project → Set Configuration → Select "Nq3"
   - Build the project

2. **From Command Line**:
   ```bash
   # Build NQ1 firmware (the `default` configuration)
   "/mnt/c/Program Files/Microchip/MPLABX/v6.30/gnuBins/GnuWin32/bin/make.exe" \
     -f nbproject/Makefile-default.mk CONF=default build -j4

   # Build NQ3 firmware
   "/mnt/c/Program Files/Microchip/MPLABX/v6.30/gnuBins/GnuWin32/bin/make.exe" \
     -f nbproject/Makefile-Nq3.mk CONF=Nq3 build -j4
   ```

   Both configurations build at **-O3** with the same `tfm.c` override (#771).
   NQ3 timing and throughput numbers are therefore generated by an
   equivalently-optimized binary to NQ1's — with one documented exception:
   `default` carries a live per-file override on `FreeRTOS_tasks.c` whose
   `<C32>` optimization value is EMPTY, so the kernel compiles there with **no
   `-O` flag at all**, while `Nq3` (no such item) compiles it at -O3. That is
   pre-existing and tracked separately; see the note under "Compiler
   Optimization Level".

3. **How It Works**:
   - Each configuration includes/excludes variant-specific files
   - `NqBoardConfig_Get()` returns the appropriate board configuration
   - `NqBoardRuntimeConfig_GetDefaults()` returns the appropriate runtime defaults
   - No code changes needed - just switch configuration and rebuild

4. **Variant-Specific Files**:
   - **NQ1**: `NQ1BoardConfig.c`, `NQ1RuntimeDefaults.c`
   - **NQ3**: `NQ3BoardConfig.c`, `NQ3RuntimeDefaults.c`
